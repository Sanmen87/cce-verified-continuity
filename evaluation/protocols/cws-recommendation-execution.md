# CWS execution continuation AB/BA — derived protocol

Protocol fixed on 22 November 2026 before the first generation. This public copy omits private local paths and launcher/oracle code. Scope: execution continuation after a shared real compaction, distinct from decision-only replay, clean cross-session transfer or a new long-compaction series.

- Same IQ3_XXS model, Pi 1.5.0, context 81 920, native generation/compaction settings. Cold unload/reload with an identical load-config hash before each independent arm.
- A: current CWS next_action enabled (`assist`). B: current next_action absent (`off`), objective state projection preserved. Shared historical recommendations remain unchanged. Observe is tested deterministically; there is no third live arm.
- Order **A1, B1, B2, A2**, with independent clean Docker workspaces. Diagnostic first pair, then reversed second pair; infrastructure errors stop remaining trials, while acceptance failures remain results.
- Equal limit **eight completed tool turns per arm**. Multiple calls from one assistant response count once after all paired results. Official Pi finishTurn/action:end ends before another model request. Earlier autonomous completion is allowed. Watchdog **80 minutes/arm**, HTTP idle **480 seconds**; all termination causes recorded separately from MODEL_FINAL.
- One common frozen CRM source, contract and transcript/Ledger after a real bootstrap Pi SDK compaction. Six core mandatory requirements. Original user history remains addressable outside retained projection. Independent stage-B seed score **17/21**. No concrete implementation defect is disclosed to the solver.
- Zero-generation paired preflight: initial SDK provider packets differ only in current next_action and mode configuration digest. Later user IDs and divergent actions/transcripts are saved as technical/expected differences.
- Solver runs nonroot, network none, read-only input/control/root with bounded writable resources. No host filesystem, Docker socket or hidden oracle mount. Allowlisted host relay reaches only the local model service. Separate grader retains hidden expectations; public checker is available to the model.
- Primary: change in independent acceptance and fully accepted task rate. Secondary: edits/checks, repetition with source/results, full provider input/output/reasoning usage, first edit/check and duration, complete tool pairs and final-packet recovery integrity. Lesser reasoning/time only helps when quality and integrity remain comparable.
- Save native history/projection, source hashes, receipts, payload hashes and packing decisions. Do not convert MANDATORY into FULL, observed shell outcomes into trusted receipts, or budget stops into agent completion. Frozen scores stay unchanged.

Raw histories, prompts/reasoning, private candidate snapshots and hidden acceptance are not included in the public bundle. The offline verifier supports arithmetic/inventory checks, not blind live reproduction.
