# CCE v0.4: сравнение и выводы

На 411 файлах и 36 фиксированных запросах оригинальная Elara сейчас лучше TS по размеченному retrieval: Recall@10 69.44% против 55.56%, MRR 0.47 против 0.35. Native порт работает полностью локально на Windows, но качество/скорость/память пока не дают оснований заменять им исходный backend для benchmark success.

Подтверждено различие candidate populations (2302 Python chunks, 7684 TS chunks): TS дополнительно допускает короткие properties/imports и более полные AST spans. Numeric FTS5/vector/RRF golden совпали на одинаковых входах. Гипотеза: маленькие структурные chunks занимают места полноценных определений; overlap dedup может дополнительно вытеснять parent class, если внутренний property/method ранжирован выше. Для причинного вывода нужен отдельный заранее фиксированный ablation, не новая настройка под уже увиденные gold queries. Возможны также различия redaction, UTF-8/line ending view, FTS document statistics и deterministic tie order. Не сводим все промахи к локальной LLM: она в retrieval эксперименте вообще не решала coding tasks.

Конкретные потери относительно Python: q06 (UserProfile); q07 (Django Payment model); q10 (Django Reminder model); q19 (contact company relationship); q28 (where is shared base model validation implemented). Для Payment Python первым возвращает class crm/models/payment.py:90–172, TS — property crm/site/paymentinline.py:10. Для Reminder TS начинает с property reminderform.py:10 и property models.py:164–166, а class Reminder с line 140 не попадает в top10. Для UserProfile вверху TS выдачи property/imports. Это наблюдения из сохранённых source spans, не доказательство единственной причины. Полные пары выдачи — benchmarks/retrieval/regressions-v04.json.

Первое измерение выявило конкретный speed bottleneck: scalar vec0 access вместо native KNN. Adaptive tie-safe KNN устранил большую часть задержки с сохранением всех ranked source ranges. Остаток TS latency включает десериализацию всех chunk payloads, inventory и source/AST validation; профилирование этих компонентов — следующий шаг. Проверенная целостность стоит дополнительной работы, но размер metadata/полные all-chunk reads тоже требуют оптимизации. RSS samples и SQLite/WAL sizes не смешиваются с точным process high-water mark.

TS graph богаче исходного pipeline, однако static links маркированы как syntax/inferred и не доказывают runtime dispatch. В query benchmark graph/literal выключены обеим arms. Реальный Django Deal прошёл независимую проверку всех 14 declared relations через межфайловое наследование. Это validation функциональности, не доказательство повышения Recall@10 от graph expansion.

Memory: original SessionCapture сохраняет decisions/code areas на диск и читает после создания нового объекта; у этих записей нет source SHA/Git freshness. Новый TS ProjectMemory сохраняет proposals/explicit confirmation/evidence и сообщает stale after source/Git change. Task Checkpoint Manager остаётся отдельным структурированным механизмом продолжения задачи, с project/session binding. Real Pi SDK restart/staleness и checkpoint session separation проверены. Наличие памяти не подтверждает истинность записанных утверждений. Полная end-to-end Elara hook memory через реальную LLM не запускалась.

Средний TS source payload меньше на 41.56% при худшем retrieval. Это не установленная экономия LLM tokens. Coding success, provider input/output и compactions неизвестны: full native agent trials NOT RUN. Показатели "94% savings" из описания upstream не воспроизводились и здесь не заявляются.

Сопровождение: TS исключает второй runtime из production, сохраняет универсальные language/framework adapters и старые checkpoints/Pi режимы. Цена — WASM assets, две SQLite структуры и собственное сопровождение security/invalidation/graph semantics. Python reference уже содержит больше production integrations и языков; TS полноценно проверен на Python/TS/JS/TSX, для остальных безопасный text fallback. Native API/model versions pinned; более новые версии не проверялись.
